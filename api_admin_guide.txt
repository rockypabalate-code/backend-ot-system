This guide covers all current Admin and HR endpoints. It begins with the final

FINAL APPROVAL FLOW
===================

1. Admin or HR logs in.
2. Admin or HR confirms that their saved signature exists.
3. Admin or HR lists pending Department Plan approval records.
4. Admin or HR opens the Department Plan approval details.
5. Admin or HR verifies every Supervisor and Japanese Management step is approved.
6. Admin or HR performs final approval.
7. Backend changes the Department Plan to approved.
8. Backend automatically creates the Actual OT period and daily entries.
9. Admin or HR lists final approved Department Plans.
10. Admin or HR manually generates the official signed OT Plan Excel when needed.

COMMON FINAL APPROVAL ERRORS
============================

Preliminary approvals are not finished:
  Status: 400
  {
    "message": "Supervisor and Japanese Management approvals must be completed before HR/Admin final approval.",
    "code": "PRELIMINARY_APPROVALS_PENDING"
  }

Admin has no saved signature:
  Status: 400
  {
    "message": "Save a signature before approving this Department OT Plan.",
    "code": "SIGNATURE_REQUIRED"
  }

Plan is no longer pending approval:
  Status: 400
  {
    "message": "Only department plans pending approval can be approved.",
    "code": "PLAN_NOT_PENDING_APPROVAL"
  }

No pending final approval is available:
  Status: 403
  {
    "message": "You are not assigned as a pending approver for this department OT plan.",
    "code": "NOT_ASSIGNED_APPROVER"
  }

Approval was already processed:
  Status: 409
  {
    "message": "This approval was already processed.",
    "code": "APPROVAL_ALREADY_PROCESSED"
  }

Excel generation is separate from final approval. If generation fails, the
Department Plan remains approved. Do not approve it again; retry Section 7.

        "plannedHours": 3,
        "reason": "Urgent order completion."
      }
    ]
  }

6. Update one Plan item
  PATCH /api/overtime/plans/:planId/items/:itemId

  {
    "employeeId": "EMP-001",
    "plannedDate": "2026-08-12",
    "plannedHours": 2,
    "reason": "Adjusted planned overtime."
  }

7. Delete one Plan item
  DELETE /api/overtime/plans/:planId/items/:itemId

8. Delete an editable Plan
  DELETE /api/overtime/plans/:planId

  Normal deletion is limited to draft, returned, or rejected Plans.


G. OT PLAN STATUS AND APPROVAL WORKFLOW
=======================================

1. Submit an Employee Plan or start a Department Plan approval
  PATCH /api/overtime/plans/:planId/submit

  {
    "remarks": "Submitted for review and approval."
  }

2. Start Department approval explicitly
  PATCH /api/overtime/plans/:planId/start-approval

  {
    "remarks": "Department Plan submitted to the assigned approval route."
  }

3. Approve assigned Department approval step
  PATCH /api/overtime/plans/:planId/approval/approve

  {
    "remarks": "Final HR/Admin approval completed."
  }

  The caller must match the pending assigned step. Final approval creates Actual
  OT automatically but does not generate Excel automatically.

4. Return/reject assigned Department approval step
  PATCH /api/overtime/plans/:planId/approval/reject

  {
    "remarks": "Returned for correction of planned hours."
  }

5. Legacy direct approval for a non-Department Plan
  PATCH /api/overtime/plans/:planId/approve

  {
    "remarks": "Approved by HR."
  }

6. Legacy direct rejection for a non-Department Plan
  PATCH /api/overtime/plans/:planId/reject

  {
    "remarks": "Rejected after review."
  }

  Department Plans must use the configured approval route, not endpoints 5-6.

7. Close an approved Plan
  PATCH /api/overtime/plans/:planId/close

  {
    "remarks": "Closed after the official Plan Excel was generated."
  }

  Generate the Department Plan Excel before closing. Current Plan Excel
  generation requires status approved, while close changes it to closed.

8. Correct/reset Plan status
  PATCH /api/overtime/plans/:planId/reset-status

  {
    "newStatus": "draft",
    "remarks": "Administrative status correction before Actual OT creation."
  }

  A Department Plan with linked Actual OT cannot be reset. Use Admin purge-data
  only when permanent deletion is genuinely intended.

9. Employee Plan signature endpoint is not available to Admin/HR
  PATCH /api/overtime/plans/:planId/sign

  Only the Employee or Supervisor can perform the confirmation/signing action.

10. Supervisor accept/return endpoints are not available to Admin/HR
  PATCH /api/overtime/plans/:planId/supervisor-accept
  PATCH /api/overtime/plans/:planId/supervisor-return

I. ACTUAL OVERTIME TRACKING
===========================

1. List Actual OT periods
  GET /api/overtime/actual-periods

  Supported filters:
    status=open or finalized, departmentId, dateFrom, dateTo

  Example:
    GET /api/overtime/actual-periods?departmentId=DEP-PRODUCTION-RTD&status=open&dateFrom=2026-08-10&dateTo=2026-08-16

2. Get Actual OT period, entries, adjustments, and comments
  GET /api/overtime/actual-periods/:actualPeriodId

3. Adjust Actual OT hours
  PATCH /api/overtime/actual-entries/:actualEntryId

  {
    "actualHours": 2.5,
    "remarks": "Adjusted using the verified timekeeping record."
  }

  Start and end times are not stored. actualHours and audit remarks are required.

4. Add Actual OT comment
  POST /api/overtime/actual-entries/:actualEntryId/comments

  {
    "remarks": "Verified the employee's concern with the supervisor."
  }

5. Finalize and lock Actual OT period
  PATCH /api/overtime/actual-periods/:actualPeriodId/finalize

  {
    "remarks": "Weekly timekeeping review is complete."
  }

  Only Admin/HR can finalize. The period must contain entries. Current backend
  does not require the period end date to have passed. Finalization locks hour
  adjustments and new comments, and does not generate Excel automatically.

6. Manually generate final Actual OT Excel
  POST /api/overtime/actual-periods/:actualPeriodId/final-document/generate

  First generation or retry:
  {}

  Replace an existing ready document:
  {
    "force": true
  }

  Required conditions:
    Actual OT period status is finalized.
    Accepted Employee Plan signature exists for every Actual OT entry.
    Approval signature snapshots and HR/Admin final approval exist.

7. Get generated Actual OT Excel signed URL
  GET /api/overtime/actual-periods/:actualPeriodId/final-document


ADMIN/HR RECOMMENDED END-TO-END ORDER
=====================================

1. Admin creates accounts and uploads signature images.
2. Admin/HR creates departments and employee profiles.
3. Admin/HR configures the department approval route.
4. Employees submit/sign Plans; Supervisors accept them.
5. Admin/HR or Supervisor compiles the Department Plan.
6. Assigned Supervisor and Japanese Management complete their steps.
7. Admin/HR completes final approval.
8. Backend creates Actual OT automatically.
9. Admin/HR manually generates the approved Department Plan Excel.
10. Optionally close the approved OT Plan after its Excel is generated.
11. Admin/HR and Supervisor review Actual OT hours; users add concerns.
12. Admin/HR finalizes Actual OT after timekeeping review.
13. Admin/HR manually generates the final Actual OT Excel.

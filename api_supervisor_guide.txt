Authentication
--------------
Protected endpoints require this header:
  Authorization: Bearer <token>

Tokens are returned by:
  POST /api/auth/login

Default token expiry:
  1 hour, unless AUTH_TOKEN_EXPIRES_IN_SECONDS is changed.


IMPORTANT SUPERVISOR ACCOUNT RULE
=================================

The supervisor role is:
  supervisor

A supervisor account must be:
  1. active
  2. linked to an employee profile
  3. linked employee profile must have a departmentId

The linked employee department controls what the supervisor can see or manage.
For most supervisor endpoints, the backend automatically scopes data to the
supervisor's own department.

If the supervisor account is not linked to an employee profile, many overtime
endpoints return 403:
  {
    "message": "Your account is not linked to an employee profile."
  }

SUPERVISOR SETUP WORKFLOW
=========================

1. Admin creates a supervisor account:
   POST /api/admin/users
   or
   POST /api/auth/register

Example body:
  {
    "firstName": "Maria",
    "lastName": "Santos",
    "email": "supervisor@example.com",
    "password": "Supervisor@123",
    "role": "supervisor",
    "status": "active"
  }

2. Admin or HR creates a department if needed:
   POST /api/overtime/departments

Example body:
  {
    "departmentName": "Production"
  }

3. Admin or HR links the supervisor account to an employee profile:
   POST /api/overtime/employees

Example body:
  {
    "userId": "user-...",
    "departmentId": "DEP-...",
    "position": "Supervisor",
    "shift": "day",
    "employmentType": "regular"
  }

4. Admin or HR links employees in the same department to this supervisor:
   POST /api/overtime/employees
   or
   PATCH /api/overtime/employees/:employeeId

Example employee body:
  {
    "userId": "user-...",
    "departmentId": "DEP-...",
    "position": "Operator",
    "shift": "day",
    "employmentType": "regular",
    "supervisorUserId": "supervisor-user-id"
  }

5. Log in as supervisor:
   POST /api/auth/login

12. CREATE DEPARTMENT PLAN FROM ACCEPTED EMPLOYEE PLANS
=======================================================

Endpoint:
  POST /api/overtime/plans/department/from-drafts

Auth:
  Required supervisor token

Purpose:
  Build a department-scope overtime plan from accepted employee plans for the
  same department and period.

Request body:
  {
    "periodType": "weekly",
    "periodStartDate": "2026-07-27",
    "periodEndDate": "2026-08-02",
    "remarks": "Department weekly OT plan"
  }

For supervisor role:
  departmentId and supervisorUserId in the request body are ignored. The
  backend always uses the authenticated supervisor's linked department and
  assignment scope.

Rules:
  There must be at least one employee plan with status supervisor_accepted for
  the department and period.
  Every copied employee plan must have an active signature made by that
  employee using confirmationMethod=self.
  Only employees assigned to the authenticated supervisor are copied.
  Only one Department OT Plan can exist for the same department and period.

Success response:
  Status: 201
  {
    "overtimePlan": {
      "planId": "DEPTPLAN-...",
      "departmentId": "DEP-...",
      "periodType": "weekly",
      "periodStartDate": "2026-07-27",
      "periodEndDate": "2026-08-02",
      "status": "draft",
      "planScope": "department",
      "items": [
        {
          "employeeId": "EMP-...",
          "plannedDate": "2026-07-27",
          "plannedHours": 3,
          "reason": "Production support",
          "sourceEmployeePlanId": "PLAN-..."
        }
      ]
    }
  }

Error responses:
  400 - No supervisor-accepted employee OT plans found for this period.
  400 - Accepted employee plans do not contain plan items.
  403 - Only supervisor, admin, or HR can create department OT plans from employee drafts.
  409 - A supervisor-accepted employee plan is missing an active employee self-signature.
  409 - A Department OT Plan already exists for this period.

21. SUBMIT DEPARTMENT PLAN TO APPROVAL ROUTE
============================================

Recommended supervisor endpoint:
  PATCH /api/overtime/plans/:planId/department-submit-and-sign

Compatible endpoint:
  PATCH /api/overtime/plans/:planId/start-approval

Auth:
  Required supervisor token

Purpose:
  Submit a department-scope plan into the assigned approval route and apply the
  authenticated supervisor's saved signature automatically. The supervisor
  approval is completed in the same transaction and the plan advances to
  Japanese Management, then HR/Admin final approval.

Request body:
  {
    "remarks": "Submitted for assigned approval"
  }

Rules:
  Plan must be department scope.
  Plan status must be draft or returned_for_revision.
  Plan must contain at least one item.
  The department must have an active approval route.
  The authenticated supervisor must be the assigned supervisor approver.
  The supervisor must have an active saved signature.

Success response:
  Status: 200
  {
    "overtimePlan": {
      "planId": "DEPTPLAN-...",
      "status": "pending_approval",
      "departmentSubmittedBy": "supervisor-user-id",
      "currentApproverRole": "japanese_management",
      "approvals": [
        {
          "approverRole": "supervisor",

SUPERVISOR TESTING WORKFLOW
===========================

1. Admin creates supervisor account:
   POST /api/admin/users

2. Admin or HR links supervisor to an employee profile:
   POST /api/overtime/employees

3. Admin or HR assigns department employees to that supervisor:
   PATCH /api/overtime/employees/:employeeId

4. Supervisor logs in:
   POST /api/auth/login

5. Supervisor checks profile:
   GET /api/auth/me

6. Supervisor reviews and adjusts Actual OT:
   GET   /api/overtime/actual-periods
   GET   /api/overtime/actual-periods/:actualPeriodId
   PATCH /api/overtime/actual-entries/:actualEntryId

7. Supervisor reviews employee OT plans:
   GET   /api/overtime/plans/supervisor-dashboard
   GET   /api/overtime/plans/:planId
   PATCH /api/overtime/plans/:planId/supervisor-accept
   PATCH /api/overtime/plans/:planId/supervisor-return

8. Supervisor creates department plan:
   POST  /api/overtime/plans/department/from-drafts

9. Supervisor submits department plan for assigned approval:
   PATCH /api/overtime/plans/:planId/department-submit-and-sign

10. Japanese Management and HR/Admin handle the remaining approval steps.
    The supervisor step was signed and completed automatically during step 9.

11. Supervisor views assigned department approval steps when applicable:
   GET   /api/overtime/plans/pending-approvals
   PATCH /api/overtime/plans/:planId/approval/approve
   PATCH /api/overtime/plans/:planId/approval/reject

For complete Actual OT request and response examples, see:
  api_actual_overtime_guide.txt


NOTES FOR FRONTEND / CLIENT IMPLEMENTATION
==========================================

Use "role": "supervisor" to identify supervisor-level accounts.

Supervisor screens should be department-focused:
  assigned employee Actual OT
  pending overtime approvals
  employee plan submissions
  supervisor plan dashboard
  department plan creation
  assigned approval steps

Do not show these actions to supervisors:
  create department
  create employee
  edit employee
  create approval route
  edit approval route assignments
  mark actual overtime as paid
  direct approve/reject plan endpoints
  reset plan status
  admin account management


Overtime plan statuses:
  draft
  submitted
  submitted_to_supervisor
  supervisor_returned
  supervisor_accepted
  pending_approval
  returned_for_revision
  approved
  rejected
  closed

Approval step statuses:
  pending
  approved
  rejected
  skipped
